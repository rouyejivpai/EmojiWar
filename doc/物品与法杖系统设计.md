## 0. 冻结范围（一句话）

**法术是实体卡、法杖是程序槽、左右手都是法杖、魔力与充能是真限制；物品只从商店与初始装备获得；UI 用一套可复用拖拽 + 插槽组件驱动，所有改动最终编译成纯数值快照进入确定性模拟。**

明确**不做**（本轮）：地面掉落与拾取、波次奖励、材料、被动槽、消耗品类目、使用效果、Shift 分堆、右键菜单、触屏/手柄、正式美术（继续 emoji）。

- `ComputeStateHash` 只混位置/血量/子弹 → 新玩法字段必须补入；
- **全项目零拖拽代码**。

## 3. 运行时模型

```csharp
public sealed class ItemInstance { int ItemId; int Count; int InstanceId; int[] SpellSlots; }  // SpellSlots 仅法杖
public sealed class ItemContainer { string ContainerId; int Capacity; ItemInstance[] Slots; event Action<int> SlotChanged; }
public readonly struct SlotRef { string ContainerId; int Index; }
public sealed class InventoryService {
    SlotRef Register(string containerId, int capacity);
    ItemMoveResult TryMove(SlotRef from, SlotRef to, int count);   // 放入/堆叠/交换 统一入口
    bool TryBuy(string shopContainerId, int index, out ItemMoveResult r);   // 买 → 进背包空格，满则拒
    bool TrySell(SlotRef slot, out ItemMoveResult r);
}
```

**容器**：`Backpack(30)`、`Hand_L`、`Hand_R`（各 1 格，放法杖）、`HandSpells_L`、`HandSpells_R`（**手部法术槽**，物理上限 8，可用槽数由手上法杖决定）、`Shop(货架)`。
**法术=实体卡**：装到法术槽即从背包移出（`ItemInstance` 整体迁移），卸下回背包；同法术两槽需两张卡。
**法术槽属于"手"，不属于某把法杖**（用户冻结语义）：
- 每个手部槽放一把法杖，法术槽数量**由法杖决定、动态变化**（`ItemContainer.ActiveCapacity`）；
- **换杖时槽位里的法术不移动**（保留给新法杖）；只有"新杖槽数装不下的那部分"被**挤回背包**；
- 背包放不下被挤出的法术时，**换杖整笔拒绝**（原子，`MoveReason.Full`）；卸下法杖同理（手上法术全部挤回背包，放不下则拒绝卸下）。
规则（P2/P4c 实现并已被自检覆盖）：
- 空槽放入 / 同 Key 且未满堆叠则合并 / 否则整叠交换（`SwapAllowed`）/ 非法返回 `Reason`（UI 提示 + 回弹）；
- **法术槽每格 1 张、不参与堆叠**：整叠拖入空槽只抽 1 张；整叠拖入**已占用**槽 → 拒绝（`Full`）；超出当前可用槽数的下标 → `IndexInvalid`；
- 手部只接受法杖；法术槽只接受法术卡；商店货架只读（买卖走 `TryBuy/TrySell`）；
- 购买＝钱够 + 背包放得下才成交（整笔原子）；出售＝整叠卖出，**手上法杖的槽内法术先退回背包，退不下则拒绝交易**。

## 4. 法杖编程式武器

### 4.1 执行语义（本轮：序列 + 修正器 + 多重施法）
从左到右扫描 `SpellIds`：
- `Modifier` → 累积到"待应用修正集"，作用于**其后最近的一个 Projectile/Multicast 组**；
- `Multicast(N)` → 其后 N 个法术**同时**发射（各自吃当前修正集）；
- `Projectile` → 生成子弹（套用修正集 + Profile）；
- 魔力不足：**跳过并停止本次施法**（卡手）；槽位游标走完后进入 `RechargeTime` 充能，再重置游标。

### 4.2 编译桥（SO 不进 sim）

```
ItemContainer(表现层) --LoadoutCompiler--> CastProgram(纯 int/float) --SimConfigFactory--> SimPlayerConfig
LockstepSimulation.Tick -> CastResolver.Resolve(program, ref CastState) -> CastPlan -> SimBullet
```
```csharp
public readonly struct CastProgram { int WandId; int[] SpellIds; int SlotCount; float CastDelay, RechargeTime; int ManaMax; float ManaRegen; CastMode Mode; }
public struct CastState { float Mana, DelayRemaining, RechargeRemaining; int Cursor; int ProgramVersion; }
public static class CastResolver { public static CastPlan Resolve(in CastProgram p, ref CastState s, float dt); }  // 无 UnityEngine 依赖
```
- 状态 hash 必须新增：`Mana / DelayRemaining / RechargeRemaining / Cursor / ProgramVersion`（每只手各一套）；
- **双手**：`SimPlayerConfig` 扩为 `PrimaryProgram/SecondaryProgram` + 两套 `CastState`；左键/右键各自冷却；
- 表现层 `WeaponModComponent` 降级为只读视图；单机也走 sim（消除两套数值）；
- 商店池改为 `Weight/Rarity` 驱动（删除 `Range(1,6)`/`Range(1,9)` 硬编码）。

### 4.3 迁移
现版 `Mod_1..8` → 法术：`FireRateUp→Modifier(CastDelay,Add)`、`DamageUp→Modifier(Damage,Add)`、`Spread→Multicast`、`Freeze→Modifier(Element=Ice)`、`OnKill→`（触发器本轮不做，暂用 `Damage` 修正占位）。旧 `ModSO` 保留一轮做对照，P5 后删除。

## 7. 风险与红线

1. 法术解释必须在 sim、纯 int/float；资产类字段不进 sim/网络；影响推进的新字段必须进 `ComputeStateHash`。
2. 联机物品闭环缺失（`RunSession` null / 金币恒 0）要一并修，否则联机背包永远空。
3. 双武器 sim 重构 + 商店池硬编码 + 两套数值收敛，三件事都在 P5，风险最高。
4. UI 拖拽要在"不暂停"覆盖层与"暂停"面板都工作（一律 `unscaledDeltaTime`）。
5. 每阶段独立验证、独立汇报，不一次性大改。

## 9. P5 落地清单（确定性接线，精确到改动点）

> 依据现状审计（`LockstepSimulation` / `SimConfigFactory` / `NetHostLogic` / `NetClientLogic` / `SimView`）。

**① 模拟层：施法程序与魔力/充能**
- `SimPlayerConfig`：加 `Items.CastProgram PrimaryProgram; Items.CastProgram SecondaryProgram;`（外加 `LoadoutHash`）。
- `SimPlayer`：加 `Items.CastState PrimaryCast; Items.CastState SecondaryCast;`（`Mana/DelayRemaining/RechargeRemaining/Cursor/ProgramVersion`）。
- `SimConfigFactory.Build`：从 `LoadoutCompiler.CompileLoadout(...)` 填两个程序（**取代**现在直接抄 `WeaponSO.Damage/FireRate` 的做法）。
- `LockstepSimulation.Tick`：冷却判定后调用新的 `CastResolver.Resolve(in program, ref state, dt)`；`FirePrimary/FireSecondary` 依旧只吃输入意图（左键/右键），子弹数值来自 `CastPlan`。
- `ComputeStateHash`：**必须新增** 两只手的 `Mana/DelayRemaining/RechargeRemaining/Cursor/ProgramVersion` + `LoadoutHash`（否则不同步无感知）。
- 新增 `Simulation/CastResolver.cs`（纯值类型、无 UnityEngine）。语义：从左到右；`Modifier` 累积、`Multicast(N)` 取后续 N 个投射物、`Projectile` 出弹；魔力不足→卡手停止；游标走完→进入 `RechargeTime`。
- `ApplyWeapon` / `S2CWeaponUpdate`：整体被"loadout 同步"取代（见 ③），旧消息保留一版做兼容。

**② 商店：去硬编码 + 卖物品卡**
- 删除 `LockstepSimulation.cs:568` 的 `Range(1,6)`（武器）/`Range(1,9)`（Mod）硬编码，改为读 `ItemSO.Weight/Rarity` 的确定性抽取（随机源仍用 `SimRandom`）。
- 商品从"武器/Mod"改为**物品卡**（法杖/法术）：`ShopItem` 的 `Type/DataId` 换成 `ItemId`。
- 购买入口改为 `InventoryService.TryBuy`（钱够+背包放得下才成交），Host 发起、客户端跟随（新增或复用 `HandleBuyItem`）。

**③ Loadout 同步（决策 #7：Host 权威、波间编辑、开战锁定）**
- 新增消息：`C2SLoadoutEdit`（波间/商店阶段允许）+ `S2CLoadoutSync`（Host 权威下发：两只手法杖实例 Id/装填 + 背包物品卡列表 + `LoadoutHash`）。
- 开战时 Host 冻结 loadout 并广播；客户端只读镜像（`NetClientLogic` 侧不自行编译，直接吃 Host 的程序数值）。
- `NetProtocol.MsgId` 新增条目（C2S/S2C **不得复用**同一 id，见既有红线），`NetCodec.Register` + 两端 switch 同步补齐。

**④ 联机物品闭环（现版既有缺口，P5 一并修）**
- `RunSession` 现在只在单机 `BattleManager.StartBattle` 创建 → 联机恒 null、金币恒 0：改为在 `ProcedureBattle` 入口创建（Host 权威、客户端只读镜像），`sim.OnEnemyKilled` 订阅加币。
- `ItemSystem.GrantStartingLoadout()` 从 `BattleManager` 移到 Host 权威的 loadout 初始化（客户端不自行发放）。

**⑤ 表现层收敛（去掉两套数值）**
- `WeaponBase.WeaponModComponent`（`Time.time`/`Time.deltaTime` 依赖）降级为**只读视图**：数值一律读 `SimView` 快照；离线单机也走 sim（`LockstepSimulation` 本地跑），消除"单机/联机行为分歧"。
- `BattleHudForm`：能量条改吃**主手法杖魔力**（决策 #19）；"Mod 槽 N 个"换成法杖槽装填数/魔力/充能。
- `ShopForm`：栏目从"武器/Mod"改成"法杖/法术"，图标走 `ItemSO.IconSprite`。

**⑥ 验收**
- 双端 `stateHash` 逐帧一致（含新增字段）；`LoadoutHash` 双端一致。
- 客户端看到的施法结果（子弹数/伤害/魔力）与 Host 相同（联机 Mod 终于生效）。
- AutoPlay：`-autoitems` 17/17、`-autodrag` 拖拽事务通过、`verify_bag.ps1` 全绿。

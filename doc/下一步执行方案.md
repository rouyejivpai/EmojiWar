## 2. 全局约束与通用验收

### 2.1 确定性约束（沿用 MIGRATION_PLAN §10.4，重申）

- 模拟路径中禁止出现：`UnityEngine.Random`、`Time.*`、协程等待、依赖字典遍历顺序的逻辑、读取表现层或系统时钟。
- 所有影响模拟的操作必须**随输入帧（FrameEvent）携带，在帧首应用**。包括购买、玩家离开、托管、调试命令等。**禁止在收到网络消息时直接修改模拟**。
- 模拟内部标识玩家**只用 EntityId**，不能用 SessionId，因为 SessionId 是房主本地的连接编号，客户端并不知道。

### 2.2 确定性回归（每个改到模拟的步骤都要跑）

1. 构建版双实例（`-autocreate` / `-autojoin`）跑满至少 2 波。用 `tools/trace_diff.py` 对比两端的 trace，**结果必须完全一致**。
2. 运行时状态对账（S2CStateCheck）**不能出现任何脱节告警**。
3. 同进程连跑两局（AutoPlay run2），第二局不能残留上一局的对象。
4. S1 完成后，另外要求 **EditMode 测试全部通过**。

### S4　经济系统移入模拟（D2 / D3）【严重】

**现状**：
- 模拟里没有金币字段。
- HUD 和商店界面读的是 `RunSession.Instance`，但联机时它根本不会被创建，所以金币显示恒为 0。

- 房主处理购买的 `HandleBuyItem` 不检查商店是否开放、不检查价格、也不扣钱（NetHostLogic.cs:1248-1315）。
- 房主本人购买时，`ShopForm.cs:186` 只查找 `NetClientLogic`，因此大概率没有任何反应。（推测，取决于房主是否也挂了 NetClientLogic。）

**执行**：
1. 给 `SimPlayer` 增加 `Coins` 字段（整数），并加入状态哈希和 trace 检查点。
2. **击杀奖励**：敌人死亡结算时，给每个**存活**玩家加上完整奖励（D3）。奖励数值从配置读取。
3. **购买**：统一走帧事件 `BuyItem(EntityId, 货架槽位)`，在帧首应用。在模拟内部依次校验：
   - 商店处于开放状态；
   - 槽位有效；
   - 金币不少于价格。

   校验通过就扣款并发放物品，失败则忽略。三端用同一份规则判断，结果天然一致。
4. **房主与客户端使用同一个购买入口**：提供一个统一的玩法指令接口（例如 `INetGameplay.RequestBuy`）：
   - 房主实现时，把指令放入本地帧事件队列；
   - 客户端实现时，把指令发往房主。

   界面层只调用这个接口，不用关心自己是房主还是客户端。
5. HUD 和商店界面**只读取模拟状态**，不再读 `RunSession` 或 `FindObjectOfType<PlayerEntity>`。
6. 删除两处重复的价格常量（ShopManager.cs:47-48 与 LockstepSimulation.cs:157-158），只保留配置中的那一份。

**需要作者决定**：商店货架是全队共享一份（一个玩家买走后，其他人就看不到这件商品），还是每人各自一份？请作者确认后再实现第 3 步。

**验收**：
- 双实例测试中，两端的金币数值完全一致，并且出现在 trace 中。
- 余额不足时购买被拒绝。

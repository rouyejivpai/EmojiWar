## 1. 概述

### 1.1 核心概念

以"法术编程"为核心的战斗施法系统：玩家把物品按顺序排成**施法序列**，一次发射**依次触发序列中每个物品的效果**。物品既是效果载体，也是修饰器、事件监听器与状态容器。✅

与 Noita 的区别：✅

| | Noita | 本设计 |
|---|---|---|
| 一次施法的取法 | 从法术链中抽取**一个**法术组合并执行 | **依次触发序列中每个物品**，形成程序流 |
| 序列长度 | 由法杖槽位固定 | 由法杖槽位决定，**可动态变化**（换杖即换槽数）|

### 1.2 系统层级

| 层级 | 名称 | 说明 |
|---|---|---|
| 第一层 | **主动物品** | 按顺序执行的主程序 |
| 第二层 | **修饰器物品** | 修改后续物品的耗蓝、延迟、充能 |
| 第三层 | **临时 Buff** | 附着在物品上的限时状态，可叠加 |
| 第四层 | **被动物品** | 事件驱动的监听器与回调 |

四层叠加后可编写复杂"法术程序"，并围绕**蓝耗 / 延迟 / 充能**三个核心属性做资源管理。✅

### 1.3 与现有工程的关系 📌

| 本设计概念 | 现有实现 | 关系 |
|---|---|---|
| 一只手 | `ItemSystem.Hand_L` / `Hand_R`（`UiSlotContainer` = `WandHand`） | 每个手部槽放一把法杖 ✅ |
| 一只手的一套法术 | `HandSpells_L` / `HandSpells_R`（`SlotKind.WandSpellSlots`，`ActiveCapacity` = 法杖槽数，**无法杖 = 0 槽**）✅ | **法术序列 = 该手的法术槽内容**（法术槽属于"手"，换杖保留、装不下挤回背包）✅ |
| 物品（主动/修饰/被动/buff 施加） | `SpellSO`（当前仅 `Kind`=Projectile/Modifier/Multicast） | ✅Q8：**扩展为"通用物品卡"**（含 TriggerType/Tags/修正/Effect/Buff/Passive） |
| 法杖 | `WandSO`（槽数 / CastDelay / RechargeTime / ManaMax / ManaRegen / Mode / DefaultSpellIds） | 法杖只提供**框架与资源**，不提供伤害 ✅ |
| 施法程序 | `Items/CastProgram` + `Items/LoadoutCompiler`（按手编译，纯 int/float） | 本设计的"序列"编译目标 |
| 施法解释 | `Simulation/CastResolver`（当前：序列+修正器+多重施法+魔力/充能，冷却=1/射速 模型已废弃） | ⚠️ 需按本设计重写（见 §2、§8） |
| 物品卡实例 | `ItemInstance`（`ItemId/Count/InstanceId/SpellSlots`） | ✅Q4：临时 Buff **挂在它上面**（随卡移动、跨施法保留、进哈希） |

## 2. 底层规则

### 2.1 施法序列

- 发射时，从序列第一个物品开始，**依次触发每个物品的效果**。✅
- 每个物品触发后，可能修改后续物品属性，或插入/移除/跳过物品。✅
- 序列全部执行完，或遇到中止/充能限制，本次施法结束。✅
- 📌 序列长度 = 该手法杖的槽数（动态）；**空杖（0 法术）= 不施法、不进冷却** ✅（已实现）。

### 2.2 物品核心属性

| 属性 | 含义 |
|---|---|
| 效果 | 触发时产生什么结果 |
| 耗蓝 | 触发该物品需要消耗的魔力 |
| 延迟修正 | 影响本次施法中后续物品的触发间隔 |
| 充能修正 | 影响本次施法后、下一次施法前的冷却 |
| 触发类型 | 立即/延迟/条件/持续/触发式/终止/被动（见 §2.5） |
| 目标 | 自身、投射物、后续物品、序列、敌人、环境 |
| 标签 | 用于交互：火焰/冰/物理/闪电/能量/虚空/灵魂/时间/召唤/投射物/修饰/终止…（见 §5.5） |

### 2.3 施法流程（每帧推进）

1. **构建序列**：按玩家排列顺序读取该手法术槽物品（跳过空槽）。
2. **初始化施法状态**：当前法力、当前延迟倍率/加值、当前充能倍率/加值、序列指针、临时修饰器列表。
3. **依次执行物品**：检查法力 → 支付耗蓝 → 应用即时效果 → 写入延迟/充能修正 → 处理对后续物品/序列的交互 → 指针后移。
4. **本次施法结束**：按累计充能修正计算下一次施法冷却 → 清空临时修饰器 → 序列修改按 §2.6 规则处理。

📌 关键工程含义（Q3 ✅ 接受跨帧）：延迟为 0 时后续物品"同一帧触发"；延迟 > 0 则**跨帧** —— 在 20Hz 定步长下需要一个**确定性的延迟队列**（每帧推进待触发列表），即"一次施法可能跨多帧"。这是与当前实现（一次按键只走一个槽位）最大的结构差异。

### 2.4 关键属性运算

```
实际耗蓝 = 基础耗蓝 × 当前耗蓝倍率 + 当前耗蓝加值
最终蓝耗 = max(0, 实际耗蓝)
```
- 法力不足：**执行到该物品时终止本次发射**；之前已执行的物品正常结算（耗蓝/效果不回退），未执行物品完全跳过（不扣蓝、不产生效果、不贡献延迟/充能修正）。✅（Q2）
  - 本次充能按**已执行物品累计**的充能修正结算（Q2b）✅
  - 中止同样触发"施法结束"事件（Q2c）✅，便于终结符文/序列清空类被动生效

```
当前延迟 = 基础延迟 × 当前延迟倍率 + 当前延迟加值
最终延迟 = max(0, 当前延迟)
```
- 延迟 0 → 后续物品同帧触发；延迟为负可提前触发但设下限。✅
```
本次施法总充能 = 基础充能 + Σ(物品充能修正 × 当前充能倍率)
最终充能 = max(0, 本次施法总充能)
```
- 充能修正可正可负；总充能为负取下限 0。✅

### 2.5 触发类型

| 类型 | 说明 |
|---|---|
| 立即 | 轮到它时立刻触发 |
| 延迟 | 等待指定时间后触发 |
| 条件 | 满足条件时触发，否则跳过 |
| 持续 | 一段时间内持续影响后续物品 |
| 触发式 | 被其他物品触发时才生效 |
| 终止 | 结束本次施法 |
| 被动 | 事件发生时触发，不占用主序列指针 |

### 2.6 序列修改规则

- 插入的物品默认**临时**，本次施法结束消失。✅
- 移除/跳过只影响本次施法，除非带"永久"标签。✅
- 序列重排只影响本次施法。✅
- 序列被清空 → 本次施法立即结束；指针越界 → 本次施法结束。✅
- 📌（Q7 ✅）防无限循环上限：单次施法**总触发 ≤64**、**单物品 ≤8**、**被动嵌套 ≤3**。

### 2.7 法力与充能平衡

- 法力是**本次施法内**的资源（从法力池扣）；充能是**施法后**的冷却，不影响本次内部。✅
- 高耗蓝物品通常强效果，但会限制后续物品触发。✅
- 负充能物品加快循环但有代价；延迟修正可制造爆发或分散输出。✅
- 📌（Q9 ✅ 见 §12）满序列资源预算表：把本设计的耗蓝/延迟/充能量级与现有法杖数值（魔力 80/140、CastDelay 0.25/0.35s、Recharge 0.9/1.2s）对齐。

## 3. 临时 Buff 系统

### 3.1 定位

临时 buff 是**附着在物品实例上的限时状态**（不是玩家状态、不是全局状态）。✅

| | 修饰器物品 | 临时 Buff |
|---|---|---|
| 存在形式 | 序列中的一个物品 | 附着在某个物品上的状态 |
| 作用时机 | 轮到它时修改后续 | 持续时间内持续修改目标 |
| 持续时间 | 通常本次施法内 | 按时间/触发次数/施法次数计 |
| 叠加方式 | 按顺序覆盖或叠加 | 可叠加，有层数与上限 |
| 影响对象 | 后续物品、序列 | 单个物品、标签组、整个序列 |

一句话：**修饰器物品是"指令"，临时 buff 是"状态"。** ✅

### 3.2 Buff 属性

名称 / 效果（改哪个属性、怎么改）/ 每层数值 / 当前层数 / 层数上限 / 持续时间（或剩余触发次数）/ 计时方式 / 作用对象 / 叠加规则。✅

### 3.3 计时方式

时间型（X 秒）、次数型（再触发 X 次）、施法型（再施法 X 次）。**推荐默认：次数型**。✅

### 3.4 叠加规则

加法叠加 / 乘法叠加 / 取最高 / 刷新时间 / 独立共存。✅ 推荐：数值型用加法，倍率型用乘法（设下限），控制型用取最高或刷新时间。✅

### 3.5 作用对象

单个物品 / 标签组 / 序列位置（后续 N 个）/ 整个序列 / 玩家（法杖）。✅
📌（Q4 ✅ 已定）buff 宿主 = **`ItemInstance`（物品卡实例）**：随卡移动、跨施法保留、进状态哈希。

### 3.6 Buff 与核心属性

```
最终蓝耗 = (基础蓝耗 + 蓝耗加值) × 蓝耗倍率 → max(0, …)
最终延迟 = (基础延迟 + 延迟加值) × 延迟倍率 → max(0, …)
最终充能 = (基础充能 + 充能加值) × 充能倍率 → max(0, …)
```
✅（📌 注意与 §2.4"物品自身修正"的运算顺序：建议**先物品修正 → 再 buff 修正**，写进实现口径）

### 3.7 施加与移除

- 施加：物品触发时 / 条件满足时 / 被其他物品触发时 / 消耗资源换取。✅
- 移除：时间到期 / 触发次数用完 / 施法次数用完 / 被驱散净化 / 被新 buff 覆盖 / 序列结束。✅

## 4. 被动触发系统

### 4.1 定位

一句话：**主动物品是"顺序执行"，被动物品是"事件驱动"。** ✅

| | 主动触发 | 被动触发 |
|---|---|---|
| 执行时机 | 轮到它时 | 事件发生时 |
| 占用序列指针 | 是 | 否（或用临时指针） |
| 资源消耗 | 触发时扣蓝 | 触发时扣蓝（或预扣） |
| 设计角色 | 主程序 | 事件监听器、回调 |

### 4.2 被动属性

触发事件 / 触发条件 / 触发目标 / 触发次数 / 触发顺序 / 消耗 / 冷却 / 作用范围。✅

### 4.3 触发事件类型

- **战斗**：击杀、命中、暴击、受伤、格挡、闪避、死亡。✅
- **施法**：施法开始、施法结束、物品触发、蓝耗支付、充能开始、充能结束、序列清空。✅
- **状态**：buff 获得/消失/叠层、法力低于阈值、生命低于阈值、延迟超过阈值。✅
- **环境**：进入/离开区域、时间流逝、回合开始、敌人出现。✅
- 📌（Q5 ✅ 已定）**第一版事件集合 = 施法开始/施法结束/序列清空 + 命中 + 击杀**。暴击/闪避/格挡/受伤/区域/回合/时间脉冲当前模拟层不产生，**后续版本**再做。

### 4.4 触发目标与顺序

- 目标：后续 N 个 / 前 N 个 / 标签组 / 整个序列 / 指定物品 / 自身。✅
- 顺序：顺序 / 逆序 / 并行 / 优先级 / 随机。**推荐默认：顺序触发，且不移动主序列指针**。✅

### 4.5 资源消耗模式

预扣 / 后扣 / 免费但限次。**推荐默认：后扣 + 限次**。✅
充能：被动触发默认不增加充能，强力被动可增加；也可"锁定充能"。✅

### 4.6 序列指针规则

1. 主序列指针独立；2. 被动用临时指针，执行完回到主序列；3. 被动可嵌套（默认上限 3 层）；4. 同事件可触发多个被动物品，按序列顺序执行。✅

### 4.7 被动与 Buff 结合

被动可施加 buff；buff 可改变被动条件/次数/资源消耗；被动可移除/引爆 buff。✅

## 5. 投射物系统

### 5.1 设计维度

飞行方式 / 命中方式 / 存在形式 / 资源关系 / 标签 / 与其他投射物关系 / 与 buff 关系 / 与被动关系。✅
核心原则：**每个投射物至少有一个"接口"**，能和其他机制说上话。✅

### 5.2–5.4 分类

- 飞行：直线 / 抛物线 / 追踪 / 环绕 / 滞留 / 回旋。✅
- 命中：单体 / 穿透 / 爆炸 / 弹射 / 连锁。✅
- 资源倾向：低耗蓝 / 高耗蓝 / 负充能 / 延迟换伤害。✅

### 5.5 标签体系

火焰 / 冰 / 物理 / 闪电 / 能量 / 虚空 / 灵魂 / 时间 / 召唤（+ 结构标签：投射物 / 修饰 / 终止 / 被动 / 控制 / 交互 / buff）。✅
📌（Q6b ✅ 已定）标签**只用于过滤与修正**（条件门、标签共鸣器、被动筛选），**不做元素反应**（避免组合爆炸与平衡失控）。

### 5.6–5.8 联动

- 投射物之间：合并 / 分裂 / 共鸣 / 吞噬 / 复制。✅
- 与 buff：施加 / 消耗 / 引爆 / 被 buff 影响。✅
- 与被动：命中触发 / 击杀触发 / 暴击触发。✅
- 📌（Q6 ✅ 已定）**第一版不做投射物之间的交互**（融合/吞噬/镜像/复制）；后续若做，在**施法计划构建期静态合成**（不做运行时实体合并）。

### 6.3 延迟修饰器
急速咏唱（后续 2 个延迟 ×0.5）、迟滞领域（后续 3 个 +0.3s 延迟 / 效果 ×1.3）、瞬发铭文（下一个延迟 0）。

### 6.5 控制流
条件门·火焰（下一个带火焰标签才触发）、循环符文（下一个重复 2 次）、序列倒转（后续倒序）、终止符（立即结束，充能 −0.1）。

### 6.6 交互型
共鸣水晶（复制前一个效果、蓝耗减半）、吞噬符文（吃掉下一个，蓝转自身伤害加成）、标签共鸣器·投射物（后续投射物 延迟 −0.1 / 充能 −0.05）、法术嫁接（下一个效果嫁接到前一个，合并触发）。

### 6.7 特殊
法力电池（+30 蓝，充能 +0.4）、虚空回响（本轮已触发效果再触发一次，蓝耗 ×2）、静默领域（后续 2 个不产生充能修正，蓝耗 +50%）。

### 6.8 Buff 施加
节能粉尘（后续 3 个"蓝耗 −1"，3 层 / 3 次触发）、疾风附魔（后续 2 个"延迟 −0.05"，2 层）、冷却符文（本次所有"充能 −0.1"，2 层）、叠加核心（下一个"蓝耗 −1"，5 层 / 每层 2 次）。

### 6.9 Buff 交互
净化之光（移除负面 buff）、buff 转移（前一个 → 下一个）、buff 增幅（层数 +1）、buff 固化（本次不再递减）、buff 引爆（移除全部，每层 5 伤）。

### 6.10 被动触发

### 6.11 被动交互

## 7. 确定性与网络约束 📌

| 主题 | 约束 |
|---|---|
| 时间步长 | 模拟 20Hz 定步长；所有延迟/冷却**量化到帧**（0.05s = 1 帧），禁止用 `Time.deltaTime` |
| 随机 | 只用 `SimRandom`（种固定），禁止 `UnityEngine.Random` |
| 序列解释 | 必须在模拟层（`CastResolver`），纯值类型，不读资产、不读表现层数据 |
| 编译桥 | 资产（`SpellSO/WandSO`）→ `CastProgram`（纯 int/float）→ sim；表现层只读快照 |
| 状态哈希 | 新增/改动的推进相关状态必须进 `ComputeStateHash`：两手 `Mana/Delay/Cursor/Recharge`、**延迟队列内容**、**物品卡上的 buff 层数/剩余次数** |
| 网络 | Host 权威：loadout（两手序列）编译后下发（⚠️ 待做 `S2CLoadoutSync`）；事件（命中/击杀）由 sim 产生，各端一致 |
| 表现 | 图标/动画/音效**不进 sim、不进网络**；由子弹/事件 Id 关联 |

## 12. 满序列资源预算表（Q9）📌

### 12.1 现有法杖基线（不变）

|---|---|---|---|---|---|
| 学徒法杖 | 3 | 80 | 18/s | **0.12s**（P2b-A，原 0.35） | 1.20s |
| 镜像长杖 | 5 | 140 | 26/s | **0.08s**（P2b-A，原 0.25） | 0.90s |
| 秘银重杖（新增） | 7 | 200 | 34/s | **0.06s** | 1.30s |

### 12.2 预算口径（一次发射 = 跑完整条序列）

| 指标 | 建议预算 | 理由 |
|---|---|---|
| 序列总耗蓝 Σ | **≤ 魔力池的 70%** | 留出一发备用；低于 40% 说明序列太轻、可上更强法术 |
| **序列时长**（(物品数−1)×基础延迟 + Σ物品延迟） | **≤ 1.2s** | 基础延迟已按 P2b-A 下调（0.12/0.08/0.06），此式即"一次施法"的真实时长；§12.4 三样例实测 0.34 / 0.32 / 0.97s |
| Σ物品延迟修正 | **≤ 0.15s × 槽数**（3 槽 0.45s / 5 槽 0.75s） | 延迟跨帧（20Hz：0.05s = 1 帧）；基础延迟另计，二者相加才是序列时长 |
| 序列总充能（基础 + Σ物品修正） | **0.8 ~ 1.6s** | 低于 0.8 变成"无限连喷"，高于 1.6 手感拖 |
| Σ物品充能修正 | **≤ 基础充能的 60%** | 否则不同法杖/序列的手感差异被淹没 |
| 回魔支撑连打 | `Regen × 一次发射周期（序列时长 + 总充能） ≥ 一发总耗蓝 × 0.5` | 保证"能连打两发"，否则永远是打一发等半天 |

> 📌 **执行期口径（P2 ✅ + P2b ✅ 按 A 定稿）**：
> 1. **序列内相邻触发间隔 = 该物品的施法延迟 + 法杖基础施法延迟** → `序列时长 ≈ (物品数−1) × 法杖基础延迟 + Σ(物品施法延迟)`；
> 2. 法杖基础施法延迟按 **A 方案下调**（0.12 / 0.08 / 0.06，见 §12.1），使 **序列时长 ≤ 1.2s** 的手感预算成立；
> 3. 其他执行期决策：**多重施法物品取消**（P3）、**法术卡不可堆叠**（P4）、**旧 8 法术资产删除**（P9）、**S1 先做 8 个物品**（P10）、法术槽上限**从配置读**（P1）、**所有数值一律配置驱动**（P11，见执行文档 §8）。

### 12.4 三条样例序列核算（**按 P2b=A 的新口径重算**）

> 口径：`序列时长 = (物品数−1) × 法杖基础施法延迟 + Σ(物品施法延迟)`；`一次发射周期 ≈ 序列时长 + 总充能`

**② 控制流 5 槽（镜像长杖：基础延迟 0.08／基础充能 0.9／140 蓝）**

**③ 爆发 5 槽（镜像长杖）**
